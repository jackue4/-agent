# 当前 Godot 能力与交付边界

本平台生成的是完整 Godot 4.7 工程：GDScript、场景、资源、着色器、输入映射和自动加载均可编辑。它没有节点类白名单，但不是全部 Godot 原生能力的开放环境。当前正式预览目标为共享单线程 Web 引擎及 Compatibility 渲染器。

| 功能 | 当前情况 |
| --- | --- |
| 2D/3D 场景、Control UI、信号、自定义 Resource、动画、物理、导航、TileMapLayer | 可以使用；具体行为仍需实际验收 |
| 材质、着色器、灯光、粒子 | 使用 Compatibility 支持的功能 |
| 图片、音频、GLB | 由素材入口导入；普通写文件只接受文本 |
| 存档 | 允许 user://；Web 持久化受浏览器存储设置约束 |
| HTTP、WebSocket、WebRTC、ENet、系统命令、外部文件、动态代码 | 平台主动限制，尚无面向玩家的联机能力入口 |
| C#、GDExtension、线程、计算着色器、Forward+ 效果 | 当前交付不支持 |
| 桌面和移动端原生安装包、编辑器插件 | 当前没有对应交付链路 |
| 3D 可视施工 | box/sphere/cylinder/cone；单批最多 8 个、总计 96 个；最终玩法复用同份关卡 |
| 2D 可视模块 | 根据真实设计、文件写入、任务合入、版本验收呈现模块工作台；工作台不是游戏运行结果 |

机器可读档案见 `server/capabilities.mjs`，制作工具 `project_capabilities` 可查询。写入和运行前检查显式拒绝当前不支持的线程、RenderingDevice 和非 Compatibility 渲染配置。此检查仅提供兼容性诊断，不是完整 Godot API 静态证明。

## 适合逐轮交付的产品

- 卡牌、棋盘、解谜、回合策略等以规则和界面为主的 2D 游戏，可拆成牌型、结算、小丑效果、商店等独立模块，配可玩的示例与确定性测试。
- 2D 动作、平台、射击和轻量塔防，可先做一个关卡与一个完整循环，再扩大敌人、关卡和内容。
- 轻量 3D 收集、跑跳、障碍挑战和探索，适合用真实施工场景逐步搭建，再接入玩家、物理、镜头和规则。

以上是工程路径支持的范围，不是每个品类都已达到商业成品质量。复杂长流程、多人联机、大规模 3D 内容以及原生扩展需要独立建设和专项验收。首轮 5–10 分钟交付一个可玩的核心切片，后续按内容、手感、平衡、兼容性迭代。

## 玩家参与与真实状态

点击模块工作台会聚焦底部输入。制作中建议通过 `/participation` 排队，在下一次主制作请求前加入上下文，不中断当前文件或并行任务。`queued` 表示排队；历史字段 `applied` 仅表示已送达本轮，不能用作建议已经实现的证据。若本轮已结束或使用旧代码引擎，待下一轮送达。

规划、文件保存、实际试玩和验收通过分开呈现；只有当前源码对应的完整验收才显示“本轮验收通过”。小游戏卡片上的展示物用于解释模块职责，不模拟实际游戏规则或伪造通过。真正的游戏运行仍使用不可变构建和当前浏览器的实时实例。

隐藏制作画面时只暂停场景并关闭绘制，不降低引擎的 `max_fps`。单线程 Web 下的低帧率等待会拖慢同页另一个验收实例。本次小丑牌实例观测到修改前 77 帧 / 15.35 秒（5.01 FPS），修改后规则检查 175 帧 / 2.94 秒（59.48 FPS，25 项通过）；这些是本机短时验收采样，不代表所有设备或游戏的帧率保证。

## 安全边界

源码扫描是正则限制，原生导入/检查由本地子进程执行，并不是操作系统级沙箱。当前适用于受信任的本地原型环境；开放给不受信任的公共作者之前，需要独立的执行隔离、身份与资源配额。不要将“扫描通过”当作任意代码已隔离的证明。

参考：[Godot 渲染器对照](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)、[Godot Web 导出限制](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)。
