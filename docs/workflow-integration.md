# UGC 创作工作流接入说明

调查日期：2026-10-27。目标：把任务拆分、独立协作、持续集成、真实试玩、缺陷修复和交付验收接入现有平台。

本文先记录接入前的调查依据，再描述首版实现。首版已落入 `workflow.mjs`、`task-team.mjs`、`gpagent.mjs`、`gproject.mjs`、HTTP 服务与创作预览界面；实际运行验收记录另见 `artifacts/workflow-v1/`。旧项目数据不参与隔离测试。

## 首版已经落地

完整工程链提供 `delegate_tasks` 和 `resolve_task`。默认两个独立任务并行，独立上下文和候选文件；文件归属冲突、过期基线或取消会阻止合入。协调任务负责集成、当前版本真实运行、自测与完成判定。短小修改仍可直接执行，不强制拆分。

当前工作记录、任务状态和验收证据随检查点保存在项目 JSON；各批任务的候选和错误另存于对应工程 `build/tasks/`。运行会话、连接、进程和原始测试图片不写入项目 JSON。重启后保留成果，用户点击「继续修复」后才会继续请求制作。当前工作及近期事件可恢复，本版尚未提供完整历史工作记录的检索界面。

预览包保存在 `build/builds/<buildId>.pck`，内嵌包自身的构建身份。浏览器实际绘制首帧后回传包内身份；URL 参数不能制造成功证明。源码或素材变更使旧验收失效。发布严格使用同一份已验证内容。这里的浏览器回执证明启动，不替代完整玩法测试，也不是不可信客户端的密码学证明。

## 接入前的基础与缺口（历史调查）

| 环节 | 当前事实 | 接入方向 |
| --- | --- | --- |
| 主执行链 | `server.mjs` 默认启用完整 Godot 工程，进入 `gpagent.runProjectBuilder`；经典模板/模块链路仍保留 | 优先扩展完整工程链，兼容旧项目 |
| 小队协作 | `gpagent.mjs` 的 A/B/C 是单条执行循环的角色标记；`agent.mjs` 逐个执行工具 | 独立任务拥有独立上下文、输入、文件分工、结果和错误；可并行的任务真实并行 |
| 真实工具 | 已具备工程读写、编译、原生运行、脚本交互、截图、多帧截图、auto_test 和 PCK 预览 | 复用这些工具，增加统一的证据记录和验收规则 |
| 完成判定 | `CodeSession.t_finish` 直接接收总结；服务端据 `milestone_done` 推进里程碑 | 编译、测试、构建都须与当前内容版本匹配，才能完成里程碑 |
| 质量检查 | 完整 Godot 工程的 `/check` 目前固定返回通过 | 返回真实检查结果或明确的“尚未验证”，不制造成功证据 |
| 并发写入 | `GodotProject` 的队列只在单个实例内；同项目会创建多个实例，素材落地也会导入/构建 | 同一项目共享合入与构建队列；独立任务交付候选补丁 |
| 发布 | 存在 PCK 时直接复制，不能证明它对应当前源码和测试 | 发布同一个已验证构建，保存构建摘要和证据，拒绝版本不匹配 |
| 预览确认 | 构建推送和浏览器 ready 已有；错误主要留在控制台，没有服务端版本验收回执 | 区分 build.created、preview.loaded、runtime.applied、acceptance.passed |
| 进度恢复 | 有 SSE、轮询、事件序号和重启后的继续提示；没有持久化的任务依赖与检查点 | 保存工作目标、任务、依赖、已交付文件、待修复项与证据；按连续事件序号恢复 |

只读验证：构造没有测试证据的 ProjectSession，调用 finish 后得到 `ok:true` 且 `milestone_done:M1`。该探针未调用创作服务或修改工程。真实 `/api/projects/730fb96b67/check` 返回 `ok:true, issues:[]`，源码确认这条分支没有执行 Godot 检查；这个响应不能证明游戏通过验收。

## 目标工作流

用户需求 → 调查现有工程 → 制定任务与验收 → 独立任务协作 → 合入候选改动 → 编译与试玩 → 反馈缺陷继续修复 → 展示已验证版本。

每次工作保留以下信息：

- `runId`：这次工作的唯一标识、原始需求、补充约束、当前目标和状态。
- `taskId`：任务目标、依赖、文件分工、输入版本、交付物、验收标准。
- `sourceRevision`：源码和所用素材的内容摘要；任何相关修改都会使旧验证失效。
- `buildId`：不可覆盖的构建标识及内容摘要；预览与发布都引用它。
- `evidence`：实际编译、测试断言、运行错误、截图及浏览器回执，全部标记对应版本。

任务状态使用 queued / running / applied / verified / interrupted / failed / blocked / cancelled。applied 只表示合入；整体验收完成后才是 verified。工作记录使用 running / ready / completed / partial / interrupted / cancelled / failed，ready 表示本地验收通过、等待当前构建的浏览器确认。预算用尽、用户停止或外部服务失败时允许保留部分成果，不能为了满足完成门禁陷入无法退出的循环。

## 第一阶段：验收与版本闭环

优先新增工作记录和证据模块，接入 `ProjectSession`、`runCodeChat`、check/publish 接口。

1. 开始工作时保存目标与基线；记录正在执行的任务，按检查点保存。
2. 每次源码或素材变更使旧编译、试玩与测试证据失效。
3. finish 返回 complete 或 partial；只有当前版本的必要验收通过，才推进里程碑。测试不能只看进程退出码或自称通过，需检查有效断言及任务要求。
4. 构建、预览和发布记录相同的内容版本。发布操作使用已经验证的构建，不复制不明版本的现存文件。
5. 将浏览器错误和实际加载结果回传，状态只说明证据覆盖的范围：原生测试通过不等于 Web 已运行通过。
6. 明确持久化字段，运行中的会话、进程、连接和完整测试图片不写进项目 JSON；图片作为独立证据文件存储。

## 第二阶段：真实任务协作

在第一阶段的合入和验收基础上增加受控任务委派：

- 主任务负责目标、约束、接口、集成和最终验收。
- 规则逻辑、场景表现、资料核对和测试可以拆成独立任务；短小修改保留单任务执行，避免过度拆分。
- 首版同时最多 2–3 个执行任务，设置每次工作的总调用/时间上限，所有子任务继承取消信号。
- 独立任务读取明确的工程基线，在各自候选区产生修改，不直接同时改正式工程。
- 文件所有权与依赖在开始前确定；两个任务要改同一文件时串行处理或交给集成任务。
- Windows 文件路径先统一分隔符和大小写再检查归属与保护目录，禁止以大小写变体绕过 `addons/ugc`、`.godot`、`build` 的边界。
- 候选补丁携带基线摘要；基线变化则要求重新合并，不覆盖较新的改动。
- 工程导入、构建、素材落地使用同项目共享队列。合入后的整体工程才产生可交付证据。
- 独立核对任务负责发现规则和流程缺漏，缺陷必须有复现路径、影响范围和验收方式。

## 第三阶段：用户能看见的真实过程

保留现有“场景 + 输入框 + 按需打开对话”的体验。无人机和角色状态由真实任务事件驱动，主要显示“正在搭建场景”“规则检查发现问题，正在修复”“这一版可以试玩”。详细文件、工具、截图和测试记录放在按需展开的过程视图中。

每条事件携带 runId、taskId、连续 seq 和对应版本。前端只在连续处理事件后推进游标；重连先补缺口。客户端不能把“收到构建链接”显示成“游戏已经生效”。

## 首版验收场景

1. 两个独立任务真实重叠执行，拥有不同任务 ID、上下文和交付物。
2. 两个任务申请同一文件时可检测冲突，后到任务不能覆盖先前结果。
3. 先测试通过、再修改源码后，旧测试不能让新版本完成或发布。
4. 编译失败、零有效断言、运行时错误，都不能推进已完成里程碑。
5. 浏览器加载失败时，工作记录保留失败结果；不能把原生成功当 Web 成功。
6. 平台中断后恢复未完成目标，保留已确认交付物与待修复项，不重复声称成功。
7. 用户取消时停止子任务和后续合入；已完成成果保留。
8. 旧模板项目与已有 Godot 项目仍可打开、试玩和继续修改。

现有文件与代码扫描是规则检查，不是操作系统级运行隔离。独立任务首版应保留受控工具边界；若平台以后允许不可信用户提交任意工程，需要另行实现受限执行环境，不能以“已经有扫描”作为隔离完成的证据。

## 主要代码接入点

- `server/gpagent.mjs`：ProjectSession、工具集、runProjectBuilder；主工作流与独立任务接入。
- `server/codegen.mjs`：CodeSession、finish、预算、方案结构；保留旧链兼容。
- `server/gproject.mjs`：工程文件操作、原生检查、自测、导入和构建；版本摘要与共享串行队列。
- `server/server.mjs`：Project 持久化、runCodeChat、事件、素材落地、check/restore/publish。
- `server/live.mjs`：真实游戏运行、交互结果及截图证据。
- `web/editor.js`、`web/gp.html`：过程事件、实际加载回执和错误回传。
- `gp_template/addons/ugc/ugc.gd`：游戏侧 ready、eval_result、测试结果与场景反馈。

该方案复用现有游戏能力。真实独立协作和版本验收属于工程能力，需要代码、接口与测试一起接入，单纯调整角色提示或播放小队动画无法完成这项改造。
