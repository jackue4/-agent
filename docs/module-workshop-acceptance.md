- 工人根据真实任务和文件进度行动；刷新先恢复工坊再恢复工人。跨页工作时主工人仍在入口可见，保留实际模块和动作。真实回复开始时显示“整理下一步”，不伪装成已写入代码。

- 旧源码的回执不能污染当前模块状态；只有当前源码、构建和浏览器首帧相符的完整验收才会完成。
- 原生工程提供带源码版本的实际文件清单，随工作流检查点、结束和刷新同步到工作台；已存在且同版本验收通过的模块显示完成，不存在或旧版本的模块不会被误标。最终六个工作台已在刷新后的真实浏览器画面确认通过。

## 产品范围与下一步

此示例是高可玩性的卡牌核心切片，已具备独立效果模块、明确输入输出、可运行示例和验证；没有验收完整原作全部小丑、全部盲注、长期平衡或全部屏幕尺寸。

建议沿现有分轮方式推进：先沉淀牌组、计分、效果、商店为可复用模块，再扩盲注与内容，之后做多尺寸与长局稳定性。3D 可沿现有施工场景继续接入更多构件；复杂物理、动画、网络和原生安装包应分别专项建设验收。当前 Web 能力与完全开放 Godot 原生能力有明确区别。
