# 看得见的 3D 关卡搭建

2026-10-27，首版已在本机实际验证。

## 原问题

项目 `d248f31c9e` 的实际记录：约 139 秒才一起保存入口与 770 行玩法脚本，185 秒才生成唯一游戏包。在此之前没有可应用的关卡物体数据。工程师的工作动作无法替代真实关卡的变化；早打包的文字建议也无法保证每一步可见。

## 新流程

1. 3D 首轮先设计小范围玩法，随即用 `build_scene` 分小批搭建。每批 1–8 个 upsert/remove，指定稳定 ID、形状、坐标、完整尺寸、欧拉角、颜色和是否实体碰撞。
2. 提交先校验并在工程锁内保存 `scenes/construction.json` 和 `scenes/construction.tscn`。成功后才发送完整 `construction` 快照。失败整批回滚，取消后不接受迟到写入。新 3D 首轮至少两次真实非空提交后才允许长脚本写入和委派。
3. 工地直接应用提交的物体：工程师走向真实世界坐标，物体逐个落地，单批动画有上限。刷新恢复当前快照，不伪造历史重播。更新/移除按稳定 ID 操作；旧版本不会覆盖新版本。
4. 最终游戏实例化同一个 `construction.tscn`，由共享加载器读取同一份 JSON。原生加载检查核对真正存在的场景节点、版本和对象数，缺失就阻止验收。独立导出测试另外核对形状、变换、材料和碰撞。
5. 编辑页保留“观察搭建”视角。PCK 完成只更新试玩入口；点击“试玩”才启动游戏。施工回执只确认场景已落地，不当作整游戏启动回执。用户试玩期间不注入施工动作或自动输入。
6. 工地专用照明与自动取景不改变游戏几何、颜色或碰撞。相机按照真实 AABB 让完整关卡入框；游戏可选择自己的玩法相机和灯光。
