# 制作动作与现场验收画面

> 2026-10-27 第二版已改为浏览器内真实运行验收，见 [实时验收与轻量编辑](runtime-editor-v2.md)。本文下方的 4 FPS 图像链路仅作为没有可用浏览器客户端时的原生回退观察，不再是正常编辑页面的验收播放方式。

编辑画面继续以游戏为主。编写或修复逻辑时，场景内的小人展开工作台，双手交替敲键；收到保存、停止或结束事件即停止。搭建动作仍指向实际提交的场景物体。动作是工作状态的可视反馈，不能产生保存或验收成功事件。

进入 `run_game`、`game_eval` 或 `run_test` 时，游戏区域自动展示正在执行该步骤的原生游戏视口；顶部显示当前步骤，底部逐项显示已经执行的检查。用户可切换“看制作 / 看验收”。手动进入试玩时，旁观层和画面轮询退出，实际输入不会被重复转发到玩家正在玩的实例。

## 真实画面与结果

- `UGC` 插件只在收到原生 `--ugc-watch` 参数时采集自身视口：约 4 FPS，长边最多 960 像素，JPEG；不捕获桌面或其他窗口。
- 两个图像槽与原子 metadata 文件让 Node 读取实际帧。读取器有停止、取消、进程代次检查，跳过来不及消费的帧。
- `PlaytestWatch` 按项目保留一个当前步骤和最近 8 帧。`GET /api/projects/:id/watch` 返回状态；`watch/frame?session=...&seq=...` 返回同一会话的 JPEG。过期会话或帧返回 410。
- SSE 只发开始、首帧、结束等状态；图像不写入聊天、持久项目、事件流。刷新页面通过接口恢复仍在执行或最近结束的旁观状态。
- 新步骤先清空上一场图像。画面超过 3 秒未更新会提示，不把旧图冒充实时画面。结束后可查看最后一帧。
- `run` 成功只表示启动完成，`eval` 成功只表示本步操作完成，`test` 成功只表示本次断言通过。整体交付继续受源码版本、编译、测试、构建与浏览器确认约束。
- 原生验收旁观不能代替浏览器实际启动和用户试玩检查，也不是高帧率视频。停止制作、异常与时限到达会关闭采集与对应进程。

## 验证入口

`server/test/playtest-watch*.test.mjs` 覆盖帧容量、旧会话、取消、错误状态、HTTP 图像、非持久化和真实测试步骤的中间反馈；其它原生采集与编辑界面测试分别覆盖插件和显示层。完整浏览器观察记录存放于 `artifacts/live-work-feedback/`。

2026-10-27 实测：通过平台编辑页对 `4377997782`《云庭寻珠》提交一次 5 分钟冲刺改进，159.412 秒结束。真实 `run_game`、两次 `game_eval` 和 `run_test` 均在交付前出现在窗口；规则测试中观察到从 2 项到 11 项检查的增长，记录了 21 个不同的中间帧样本。随后实际浏览器使用 R 和 Shift+W，角色位置与体力变化，手动试玩未被旁观覆盖；当前构建回执匹配后状态为 completed。

证据：`02-test-start.png`、`03-live-check.png`、`04-acceptance.png` 为制作未结束时的浏览器画面，`05-player-control.png` 为用户试玩控制。`report.json` 为步骤与中间帧采样，`final-acceptance.json` 为最终匹配版本。动作与镜头的原生测试包含 59 项工作台/镜头断言，加上既有 3D 33 项、2D 24 项；全套 Node 409 项通过，后续局部请求超时修补后前端 22 项通过。
